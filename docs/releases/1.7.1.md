# Kestrel 1.7.1 — Newly installed apps appear automatically

Kestrel now refreshes its app list in the background whenever you open the launcher, and every five seconds while it stays visible. Apps installed after Kestrel starts—including apps inside Applications subfolders—appear without restarting or using Refresh applications. Renamed and removed apps are updated too.

The previous list stays available while refreshing, so typing remains responsive. Search results update when a changed list is ready. App discovery reads the Applications folders directly and does not wait for Spotlight indexing.

## Update

Choose **Check for Updates…** in the wing menu or General settings. Automatic checks notify you; installation asks first. Settings, snippets, and clipboard history remain in place.

Official builds retain the signing identity introduced in 1.7.0. Users upgrading directly from 1.6.1 or earlier may need the [one-time Full Disk Access refresh](https://github.com/junoh-bg/kestrel/blob/main/docs/getting-started.md#one-time-permission-refresh-for-170). Full Disk Access was retained in our signed-update test; this does not guarantee that macOS will permit the app to open without a separate security approval.

## macOS may ask to allow Kestrel again

If macOS blocks opening Kestrel, use **System Settings → Privacy & Security → Open Anyway** for a trusted download, then authenticate and confirm **Open**. See the [first-launch guide](https://github.com/junoh-bg/kestrel/blob/main/docs/getting-started.md#first-launch). This app-opening approval is separate from Full Disk Access. The persistent certificate keeps the app identity consistent; it does not provide Apple Developer ID or notarization, so we cannot promise warning-free updates. Do not disable Gatekeeper. If the message says malware was detected or the app is damaged, stop and report it.
